# 性能与成本测量

- 模型：deepseek-chat
- 语料：1,251 条法条

## 冷启动（只发生一次）

| 步骤 | 耗时 |
|---|---|
| 读 1,251 条语料 | 7.7ms |
| 建 BM25 索引（切词 + 词频 + df） | 60.8ms |
| 加载 bge-m3 + 读向量矩阵 | **7956.5ms** |
| 合计 | **8024.9ms** |

> 冷启动的主要点是加载 bge-m3（模型文件约 2 GB）。
> 实际服务会把它常驻内存，只有第一次启动付这个代价。

## 单次检索（取 3 次平均）

| 检索方式 | 单次耗时 |
|---|---|
| BM25（纯计算，无模型） | 3.4ms |
| 向量（含一次 bge-m3 编码） | 182.4ms |

> 向量检索慢在「把问题编码成向量」这一步；
> 矩阵乘本身很快（1251 × 1024 一次算完）。

## Agent 端到端

| 问题 | 耗时 | 工具调用次数 | token |
|---|---|---|---|
| 试用期最长能有多久 | 4237.8ms | 2 | 2390 |
| 我工作了 3 年半，月薪 12000，被裁员 | 5190.1ms | 3 | 2966 |

> token 只统计 agent 节点自身的调用（从 `usage_metadata` 累加）；
> 工具内部的模型调用不在这份统计里。

## 合同体检

| 项 | 结果 |
|---|---|
| 合同 | sample_1.txt（8 条条款） |
| 总耗时 | **12.0 s** |
| 每条平均 | **1.5 s** |
| 每条的开销 | 1 次向量检索 + 1 次 LLM 判断 |

> 按这个速度，一份 20 条的合同约需 30 秒。
> 这部分 token 未计入上面的统计（工具内部自己开的 client）。
