# numpy vs Milvus 检索对比

- 数据量：1,251 条法条，1024 维 bge-m3 向量
- 查询：20 条（取自 golden_set），每条跑 5 次，首次丢弃

## 实测

| 项 | numpy（exact） | Milvus（HNSW, ef=64） |
|---|---|---|
| 纯检索 P50 | **0.36 ms** | **4.68 ms** |
| 纯检索 P95 | 0.42 ms | 6.06 ms |
| 编码 P50（同一个 bge-m3） | 108.30 ms | 101.35 ms |
| 元数据过滤 P50 | 0.45 ms | 4.83 ms |
| 应用侧冷启动 | 5.9 s | 5.0 s |
| 召回一致性（top-5 重合） | 基准 | **100 / 100** |

**numpy 快 13.1 倍；编码所占 99.7%；召回完全一致。**

## 什么时候该换

这个规模下 numpy 更快，所以默认用它。

数据量增长到**十万级**时再重新评估 —— 那时候需要真实扩容后重测，
外推不可靠（numpy 的 argsort 是 O(N log N)，HNSW 的图也会随数据量变大）。

## 能力对比

| 能力 | numpy | Milvus |
|---|---|---|
| 元数据过滤 | 全量打分后手写过滤 | `filter=` 一个参数 |
| 增量更新 | 重建整个 `.npy` | `upsert` / `delete` |
| 多租户隔离 | 自己维护 id  下标映射 | `filter=user_id==...` |
| 依赖 | 一个 4.9 MB 文件 | 三个容器 + 2–4 GB 内存 |
